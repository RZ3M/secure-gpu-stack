# z-ai/glm-5.3-flash

## Findings (most severe first)

**1. HIGH — sgs-check's unsafe-source check is case-sensitive, but apt's one-line source options are not.**
`bin/sgs-check:82` builds the unsafe-option regex from lowercase names: `re.search(rf"\b{o}=yes\b", opts)`. A `.list` entry like `deb [trusted=yes] http://...` is caught, but `deb [Trusted=yes] ...` (apt treats one-line option names case-insensitively — *unverified*, please confirm against apt's parser) is not, so the source is reported `PASS|host: HTTPS, key limited to this source` while apt installs its packages without signature checks. Same for `Allow-Insecure=yes`. Fix: lowercase `opts` before matching (`opts.lower()`), or use `re.I`.

**2. MEDIUM — the duplicate-source workaround is dead code on a first install.**
`install.sh:104-107` guards `disable_duplicate_sources` with `[ -e /etc/apt/sources.list.d/sgs-nvidia-cuda.sources ] && ...` — but on a *first* run that file doesn't exist yet, so a leftover entry from Docker's `curl | sh` guide or NVIDIA's `cuda-keyring` is not moved aside, and `apt-get update` at line 108 fails with "Conflicting values set for option Signed-By", aborting the whole install under `set -e`. The comment (101-103) says this case is handled; the guard defeats it. Fix: call `disable_duplicate_sources` unconditionally before the update (it already skips our own file via the `$f != "$ours"` test once ours exists; before that, ours simply isn't in the glob).

**3. MEDIUM — "Automatic security updates are on" check false-warns on a correctly installed machine.**
`bin/sgs-check:629`: `apt-config dump APT::Periodic::Unattended-Upgrade | grep -o '"[0-9]*"'` matches *every* quoted numeric value in the entire dump. The stack's own `20auto-upgrades` (install.sh:267-270) sets `Update-Package-Lists "1"` too, so the substitution yields `"1"\n"1"`, which `!= '"1"'` → `[WARN] Automatic security updates are off` on every machine the stack installed correctly. Fix: match the specific line, e.g. `apt-config dump APT::Periodic::Unattended-Upgrade | grep -q 'Unattended-Upgrade "1";'`.

**4. MEDIUM — the unrecorded-startup-code check never scans /opt/sgs/tf-cuda12.**
`bin/sgs-check:377` runs the `.pth`/`sitecustomize` scan only on `$SITE` (the venv). `/opt/sgs/tf-cuda12` is a root-owned pip `--target` tree that gets added to Python's path (and whose `.pth` files execute wherever it's on the path); a wheel installed there — or a file dropped in post-install — with a `.pth` runs in every TensorFlow process with no detection. The integrity check (456) covers it, but only against RECORDs, and a hand-dropped `.pth` isn't in any RECORD. Fix: run the same unrecorded-file scan over `/opt/sgs/tf-cuda12` (and `/opt/sgs/tools`).

**5. MEDIUM — the network-exposure check exempts anything on port 22, SSH or not.**
`bin/sgs-check:520` drops every listener with `grep -vE ':22$'` before classifying. If sshd is stopped/disabled (socket-activation means nothing listens until a connection) and malware binds `0.0.0.0:22`, the machine reports `[PASS] Only SSH listens on the network`. Fix: exclude `:22` only when `ss -tlnpH` shows the owning process is sshd.

**6. MEDIUM — CDI specs are called a trust root by sgs-check but aren't audited.**
`bin/sgs-check:300-303` warns that a modifiable CDI spec "can add host mounts and root hooks to every GPU container", but `install.sh:547-553` watches `/etc/nvidia-container-runtime/` and not `/etc/cdi/` (the persistent spec location the installer itself generates into, line 443). Changes to `/etc/cdi/*.yaml` leave no audit trail. Fix: add `/etc/cdi:sgs-gpu` to the rule list.

**7. MEDIUM (unverified) — the NVIDIA unattended-upgrades origin pattern may never match.**
`install.sh:278-281` uses `"origin=NVIDIA,label=NVIDIA"`. This only auto-installs NVIDIA's security fixes if the repo's Release file has exactly `Origin: NVIDIA` / `Label: NVIDIA`; if it's e.g. "NVIDIA Corporation" (or the label differs), cuDNN/NCCL/Container Toolkit CVE fixes never install automatically while sgs-check:629 still reports automatic updates on. Fix: verify against the actual Release file (`grep -E '^(Origin|Label)' .../Release`) and pin the pattern to what's really there.

**8. MEDIUM — Docker published-port detection breaks with `userland-proxy: false`, producing a false "firewall blocks it" note.**
`bin/sgs-check:530` identifies Docker-published ports by the `docker-proxy` process name. With `"userland-proxy": false` dockerd binds published ports itself, so they're not recognised as Docker's, skip the `via_docker` branch, and — since Docker's iptables rules bypass ufw — the check prints "The firewall blocks all of these from the network" for ports that are actually reachable. Fix: also treat dockerd-owned listeners as Docker's, or inspect the iptables DOCKER chain.

**9. LOW — the Container Toolkit version check PASSes when nvidia-ctk is broken.**
`bin/sgs-check:246-251`: if `nvidia-ctk --version` fails, `nct` is empty; `dpkg --compare-versions "" lt 1.19.1` errors out (exit 2), `version_lt` returns false, and the check prints `[PASS] NVIDIA Container Toolkit ` with an empty version. Fix: `[ -z "$nct" ] && bad "nvidia-ctk --version failed"` before comparing.

**10. LOW — pip-index check misses root's legacy config and any venv-local pip.conf.**
`bin/sgs-check:361` lists `/root/.config/pip/pip.conf` but not `/root/.pip/pip.conf`, and pip also reads `$VIRTUAL_ENV/pip.conf` — a pip.conf dropped inside a user's sgs-venv (or any venv) pointing at an attacker-controlled index is invisible to the check. Fix: add `/root/.pip/pip.conf` and scan `*/lib/python3*/pip.conf`-style venv locations, or better, dump pip's effective config (`pip config list`) for the stack interpreter.

**11. LOW — the stack-file integrity check silently disappears if its manifest is deleted.**
`bin/sgs-check:512` wraps the `files.sha256` verification in `if [ -f /opt/sgs/files.sha256 ]` with no else. On a machine where that file was removed (the exact scenario the hash list exists to catch), sgs-check prints nothing for this check and can exit 0. Fix: `else bad "The stack's integrity manifest is missing"`.

**12. LOW (unverified) — the GPU test's TensorFlow leg may always WARN because of `-I`.**
`bin/sgs-check:665` runs each framework with `"$PY" -I`. Isolated mode ignores `PYTHONPATH`, and TensorFlow's package lives in `/opt/sgs/tf-cuda12` (a `--target` tree, not on the venv's sys.path — the preload hook only preloads *libraries*, `files/sgs_cuda_preload.py:33-49`). Unless `tensorflow` is also in the venv lockfile, `import tensorflow` raises ModuleNotFoundError and the test reports `WARN|TensorFlow GPU test failed`. Unverified: depends on `files/profile-sgs.sh` and the lockfile contents, which weren't provided. Fix: run the TF leg with `PYTHONPATH=/opt/sgs/tf-cuda12` set explicitly (not via `-I`-ignored profile files).

## Checked and not found

- **`set -e` behaviour in install.sh**: I traced every bare `A && B` / `A && B || C` statement (lines 104-107, 118, 228, 358, 363, 470-474) — in each, the failing command is not the final command of the `&&` list, so `set -e` does not abort; the `make_venv` early-return at line 474 is also safe. Pipelines under `pipefail` that can fail (448, 362) only run after the packages they query are installed. No abort-on-expected-failure bug found.
- **systemd escaping in the Jupyter unit**: `$$` → literal `$` for sh, inner double quotes sit inside the outer single-quoted argument and reach `sh -c` verbatim, `%i` is only used in `Description`/`User=` where a normal Ubuntu username is safe. The one residual edge is a `--user` name containing `%` or `\` (systemd specifier/escape characters) breaking the instantiated unit — not reachable with `adduser`-created names, so I'm not counting it.
- Per instructions, I did not re-raise the two previously rejected claims (recursive audit watches, tailscale0 allowance).
